# Контекст для Claude Code: Tropa

## Что это
Пет-проект Дархана для портфолио (Go-бэкенд): карта мест Алматы и Алматинской области, куда сходить с друзьями (природа, активный отдых, места в тепле, культура), и встречи, которые собираются через карту. Не коммерческий продукт. Только Алматы и область. План и статус этапов: `docs/ROADMAP.md` (обновлять после каждого этапа).

## Стек
- Go 1.25, `net/http` ServeMux с паттернами методов, `html/template`, без JS-сборки. Шаблоны, статика и SQL-миграции встроены через `go:embed`.
- PostgreSQL через `pgx/v5` (пул `pgxpool`). Внешние зависимости — только `pgx` и `x/crypto`; Telegram — без SDK, на `net/http`.
- Интерфейс и комментарии в коде — на русском.

## Карта кода
- `cmd/tropa/main.go` — команды `serve` (миграции при старте, фоновая очистка сессий), `migrate`, `seed [папка]`, `make-admin <email>`; настройки — переменные окружения (см. шапку файла).
- `internal/store` — `Open`, `Migrate` (файлы `migrations/NNN_*.sql` по порядку, каждый в своей транзакции, под advisory lock). Новая миграция — новый файл, старые не менять.
- `internal/store/storetest` — `storetest.New(t)`: пул в новой схеме со всеми миграциями; без `TROPA_TEST_DATABASE_URL` тест пропускается.
- `internal/auth` — пользователи (bcrypt, email без учёта регистра), сессии (в БД только SHA-256 токена), `Middleware` (пользователь в контексте + CSRF double-submit для всех не-GET), `RequireUser`, `SafeNext` для редиректов.
- `internal/places` — места. `Place` (теги json = формат `data/places/*.json`), группы `Category` и виды `Kind` (`kinds`), рамки `RegionBBox`/`CityBBox` (только быстрый отсев), точные границы — `boundary.go` + `boundary.json` (полигоны OSM области relation/215718 и города relation/2465058; `InArea`, `InCity`, `AreaOf`), `Normalize` + `Validate` (area должна совпадать с `AreaOf`), `TwoGISURL` (обычная ссылка на 2gis.kz). `store.go`: `Upsert` по slug (не трогает строку, если поля те же — `IS DISTINCT FROM`), `Get` (только published), `Search(Query)`. `seed.go`: `LoadSeed` (все файлы, кроме `candidates*`, `DisallowUnknownFields`, уникальность slug и osm_ref; при ошибке — ничего), `Seed` одной транзакцией.
- `internal/osm` — импорт: `Query` (Overpass QL по `selectors`, `out tags bb`), `Client.Fetch` (повторы на 429/5xx/remark-таймаут, запасные серверы, 4xx не повторяется), `Classify` (теги → группа/вид/флаги; пики и ущелья — только `MountainsBBox`, мелкие парки и ТЦ — по размеру рамки), `Candidates` (границы, дубли по osm_ref и «то же имя в 700 м», `Slugify`, `Quotes`). Команда `osm-fetch` пишет `data/places/candidates.json`, сырой ответ кэширует в `%TEMP%/tropa-osm-raw.json` (`--from` — без сети).
- `internal/weather` — `Client.Current`: погода в Алматы из Open-Meteo (кэш 30 мин, неудача запоминается на минуту, таймаут 3 с), `Weather.Cold` (≤ 0 °C, осадки, ветер ≥ 36 км/ч) и `Summary`. Без погоды страница работает как обычно; `WEATHER_URL=off` — выключить. «Не сезон» — `Place.OffSeason(месяц)` (летние на улице — ноябрь–март, зимние — май–октябрь).
- `internal/meetups` — встречи на местах (миграция 004 удалила походы). У каждой встречи ссылка `/m/{token}` (16 случайных байт, base64url; `ByToken` — неверный токен как «нет такой»): открытые (`public`) видны в списке и на карте, `friends` — только по ссылке. `Input.Validate` (дата+время по `Almaty`, в будущем, не дальше года; мест 2–200 или пусто — без лимита), статусы `open|closed|cancelled` и ручные переходы, `Update`/`SetStatus` под `lockMeetup` (`FOR UPDATE`, затем чтение со свежими счётчиками), `ErrStaleStatus`; прошедшая или отменённая не меняется. `join.go`: организатор записан сразу; `Join` (место — `confirmed`, иначе конец очереди), `Leave` (освободилось — `fillSeats`: первому в очереди `offered` на `OfferTTL` 24 ч), `Accept`, `ExpireOffers` (воркер в `serve` раз в минуту); позиции очереди без дыр (`closeGap`, уникальность отложена до конца транзакции). `list.go` — `Filter`, `List`, `ByPlace`, `CountByPlace` (для `/api/places`), `ByOrganizer`, `ByParticipant`. `Now` подменяется в тестах.
- `internal/web` — `Server`, маршруты в `Handler()`, `render` (layout + страница, рендер в буфер), flash-сообщения по коду (`flashText`). Каждая страница — `templates/pages/*.html` с блоками `title` и `content`; общие куски (`meetup_card`) — в `layout.html`. Блоки layout: `head` (доп. CSS), `body_class` (`map-body` — страница на всю ширину), `scripts`. Карта: `places.go` — `mapPage` (главная, плашка непогоды), `apiPlaces` (`GET /api/places?bbox=s,w,n,e&cat=&indoor=1&free=1&q=` → GeoJSON, ошибки — 400 JSON), `showPlace` (`/places/{slug}`, ближайшие встречи); встречи — `meetups.go` (`/meetups`, `/places/{slug}/meetups/new`, `/m/{token}` и `/edit|status|join|leave|accept`; на странице встречи `Referrer-Policy: same-origin`, чтобы ссылка не утекала); клиент — `static/map.js` (главная и мини-карта места; текст данных только через textContent). Leaflet и markercluster — в `static/vendor`, не на CDN; CSP разрешает картинки только с tile.openstreetmap.org, Referrer-Policy `strict-origin-when-cross-origin` (плиткам OSM нужен Referer). После правки статики сервер нужно пересобрать — всё встроено через embed. Скриншоты: headless Edge не даёт окно уже 492 px — мобильную вёрстку снимать при 492. Форматирование для шаблонов (`when`, `clock` — по Алматы, `plural`) — `format.go`. В формах обязательно скрытое поле `csrf_token`.

## Данные мест
- Источник — OpenStreetMap (ODbL, подпись «© участники OpenStreetMap») и ручное курирование. **Данные 2ГИС не брать** ни API, ни парсингом: лицензия запрещает хранение (law.2gis.ru/api-rules, п. 4.2). 2ГИС — только ссылкой.
- Координаты не писать по памяти: проверять по OSM (Nominatim/Overpass, ≤ 1 запроса в секунду, User-Agent со ссылкой на репозиторий, без личных email) и указывать `osm_ref`.
- Новые места — в `data/places/*.json`, затем `go run ./cmd/tropa seed`. Разбор кандидатов: принятые переносить из `candidates.json` в `osm-*.json` со `status: published`, укорачивать slug и названия; правила первой волны — `data/places/README.md`. `TestRepoSeedFilesValid` проверяет настоящие файлы.

## Правила
- Коммиты без строк Co-Authored-By и «Generated with Claude Code»: автор только Дархан.
- Логика записи и листа ожидания — в транзакциях с блокировкой строки встречи; проверять конкурентным тестом на реальной базе.
- Перед коммитом: `gofmt -l .`, `go vet ./...`, `go test ./...` (с тестовой базой).
