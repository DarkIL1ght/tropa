# Уведомления в Telegram — настройка для владельца сайта

Пользователям сайта отдельная инструкция не нужна: она есть на самом сайте — страница `/help/telegram`, ссылка на неё в профиле.

## Что делает бот

- Пишет пользователям, у которых подключён Telegram: освободилось место во встрече (место держится 24 часа), до конца предложения 2 часа, встречу перенесли или отменили, напоминание за сутки.
- Принимает `/start <код>` (привязка аккаунта по одноразовой ссылке из профиля) и `/stop` (отключение).
- Сообщения приходят **через очередь** (`notifications`): событие и уведомление пишутся в одной транзакции, а воркер отправляет их с повторами. Если Telegram недоступен, уведомления дождутся отправки.

Без токена сайт работает как раньше, просто без уведомлений и без блока Telegram в профиле.

## 1. Создать бота

1. В Telegram откройте [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Имя (видно в чате): например, `Tropa — встречи`.
3. Username (должен заканчиваться на `bot`): например, `TropaAlmatyBot`.
4. BotFather пришлёт токен вида `123456789:AA…`. **Это пароль от бота**: не коммитьте его и не отправляйте в чаты.

Необязательно, но приятно (всё в @BotFather):
- `/setdescription` — «Уведомления о встречах на сайте Tropa: освободилось место, перенос, отмена, напоминание».
- `/setcommands` → `stop - отключить уведомления`.
- `/setuserpic` — аватар.

Это должен быть **отдельный бот** для сайта. Бот, через который вы общаетесь с Claude Code, использовать нельзя: Telegram отдаёт сообщения бота только одному получателю (`getUpdates`), и два процесса будут отбирать сообщения друг у друга.

## 2. Вписать токен

В `.env` в корне проекта (он в `.gitignore`):

```
TELEGRAM_BOT_TOKEN=123456789:AA...
SITE_URL=http://127.0.0.1:8080
```

`SITE_URL` — адрес сайта, из него строятся ссылки в сообщениях. Локально можно не задавать (по умолчанию `http://` + `ADDR`). На сервере обязательно указать настоящий адрес, например `https://tropa.example.kz`: иначе в сообщениях будут ссылки на `127.0.0.1`.

## 3. Запустить и проверить

```
go run ./cmd/tropa serve
```

В логе должно быть `уведомления в Telegram включены bot=@TropaAlmatyBot`. Если там `бот уведомлений недоступен` — неверный токен или нет сети: сайт работает, но без уведомлений.

Проверка:
1. Зарегистрируйтесь на сайте → профиль → «Подключить Telegram» → «Открыть Telegram» → «Запустить».
2. Бот ответит «Аккаунт привязан», в профиле — «Telegram подключён».
3. Со второго аккаунта соберите встречу на 2 места, займите их, первым аккаунтом встаньте в очередь, вторым — «Не пойду». Через несколько секунд придёт «Освободилось место».

## Как устроено

- Бот получает сообщения через long polling (`getUpdates`), поэтому ни публичный адрес, ни вебхук не нужны — работает и на ноутбуке, и на VPS за NAT.
- Код привязки — 18 случайных байт; в базе только его SHA-256, срок жизни 15 минут, используется один раз.
- Отправка: пачками по 20, строки «забираются» под `FOR UPDATE SKIP LOCKED`, HTTP-запросы идут вне транзакции. 429 — ждём `retry_after`, 5xx и сеть — повтор через 30 с, 1 мин, 2 мин… (до часа), после 8 попыток уведомление бросается. 403 (бот заблокирован) — Telegram у пользователя отключается.
- Запускается **один** процесс сервера на одного бота: два процесса с одним токеном будут конфликтовать на `getUpdates`.
